# afifo revision, 2026-10-16

The v1 gray-pointer golden is in `archive/v1-gray-pointer/`. Its prompts are in `experiments/prompts/archive/afifo-v1/`. Generated RTL from that task is not comparable to this contract.

v1 met the functional test and kept both clock crossings visible, but Jasper 2026.03p001 reported two raw `CNV_ST_CONV` errors on the full and empty comparisons. A proven `config_rtlds -signal -gray_code -verify` on `wgray` and `rgray` left those errors in place, with zero waivers. The installed manual's course for Gray reconvergence is a waiver. FIFO scheme mappings either dropped the memory pairs or attached to no pairs. That is a limit of the configuration experiments, not a demonstration that the gray-pointer circuit is broken.

This version keeps the module ports, the `2**LGFIFO` storage burst, ordered delivery, and reset polarity. It replaces the synchronized pointer comparison with a one-bit request and a one-bit acknowledge so full and empty are not a multi-bit reconvergence. Read throughput falls to one word per handshake round trip. `o_rd_empty` can be high while storage still holds words.

Holding `rd_ptr` until `req_level` fell was run through the functional test, the structural Jasper script, the generated protocol proofs, and metastability injection. The functional test passed. Structural errors stayed at zero with zero waivers, and both crossings stayed visible. `CDC_data_q_datapath_stable` still failed, with a 10-cycle counterexample, including under metastability injection. That pointer change is not in the golden. `data_q` still loads on the one read edge where `rphase` is 0 and `req_level` is already 1, and `rd_ptr` still advances later, on accept.

The applicable checks are in `build/jasper/afifo_v2_harness/run.tcl`. Jasper proved that `data_q` changes only on that capture edge, that `rd_ptr` is stable on that edge and advances by one on accept, that `req` and `ack` each stay high until the other side responds, and that an active offer does not write `send_ptr`. The same seven properties proved again after metastability injection. This build injected the `req` and `ack` crossings only. The generated mux check is unchanged and still fails.

The public-interface safety proof is `benchmarks/afifo/formal/integrity_prove.tcl`, log `build/jasper/afifo_v2_integrity/jg.out`. It is for the elaborated defaults only: depth 8, width 16, NFF 2, registered reads, write on the rising edge. After initialization, with both resets held released, accepted reads return the corresponding written data in order. Capacity and underflow were proved, including under metastability injection on the `req` and `ack` crossings only. `fill8` and `drain8` were covered, which shows that traffic can occur; they do not prove that every pending word is eventually read. `CDC_dut.data_q_datapath_stable` still fails and is not waived. The two reset implications prove in preprocessing with unreachable antecedents, so they are not evidence of in-reset behavior. Assumption conversion runs only after each lemma has `validity_status=proven` and `run_status=processed` on that same injected run.
